Tags are the main way Leapfrog turns raw text into a usable research structure.

## What a tag includes

Every tag can have:

- a name
- a color
- an optional description
- an optional parent tag

That lets you keep a simple flat codebook or build a hierarchy when the project needs one.

## Where tags show up

The same tag applications flow through the desktop app:

- text editors
- markdown preview
- transcript editor
- the Tags view

When you update a tag name, color, or description, Leapfrog refreshes the hover and preview surfaces so they stay aligned.

## Apply tags

You can tag selections in transcripts and supported editors. Once applied, Leapfrog stores the anchored range and shows the tag back in the relevant surface.

Use manual tagging when:

- you are building the first pass of a codebook
- you want precise control over evidence boundaries
- you are reviewing or correcting auto-tag output

## Use the Tags view

The Tags view is more than a list of labels.

You can:

- search tags by name
- expand a tag to see child tags
- expand again to see files grouped under that tag
- open the exact snippet where the tag was applied
- remove a tag from a specific selection
- edit the tag name, description, and color

## Descriptions matter

If you write short tag descriptions, Leapfrog can surface those descriptions in hover cards and keep the codebook easier to understand later.

Descriptions are also useful when you want auto-tagging to reuse the right existing tag instead of inventing a new one.

## Good workflow

Start with a small codebook, apply a few tags manually, add descriptions once the tags stabilize, then use auto-tagging to scale that structure across the workspace.
